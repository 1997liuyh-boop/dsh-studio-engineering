## 目标与现状

用户要求全面重构 UI、完善功能并落实编码准则。重构以目标目录的当前文件为起点，包括尚未提交的画布、体检、历史记录和项目档案功能。实施前保存现有差异与新增文件的副本，不能通过 reset、clean 或覆盖旧版本丢失这些成果。

现有技术为 Vue 3.5、Tailwind CSS 4、TypeScript、Node Host 插件及内置 tree-sitter 图谱引擎。根目录的 lib/static/skills 是构建同步的安装文件，源码集中在 studios/engineering。2026-11-17 的基线验证：npm run typecheck 通过；npm test 的 51 项测试通过。现有 typecheck 只覆盖 .ts，未覆盖 .vue 模板。

源码中可确认的问题：App.vue 同时管理项目、查询、图谱、详情、技能和设置；GlobalView.vue 包含十个子视图和多种请求状态；call<T> 的响应类型由调用方自行指定；页面请求没有取消或过期结果保护；添加项目后读取快照发生在统一错误处理之外；模板含 as HTMLSelectElement；编码准则只有全局开关，混在快捷任务页面。

## 方案比较

1. 仅换样式：成本低，但重复请求状态和功能入口分散的问题仍在，不符合全面重构要求。
2. 重做界面和应用层，保留可验证的解析内核：推荐。以用户任务划分页面，统一请求、状态、数据定义与错误反馈，补齐现有引擎能力的 UI 入口。
3. 全部重写解析引擎并迁移框架：风险最大，会丢失已验证的 Vue、Nuxt、uni-app 解析能力；当前测试没有提供必须替换引擎的依据。

建议采用方案二。允许删除和替换旧页面与内部接口，同时同步更新所有调用方；现有项目图谱可重新生成，已经保存的迭代文档及用户设置应保留或明确迁移。

## UI 与信息结构

将页面改成面向研发操作的工作台，使用中性背景、清晰分区和单一强调色，数字等宽，长路径可展开或复制。Tailwind 负责界面样式；颜色等基础变量集中维护；支持系统深浅色和减少动画偏好。

```text
研发工作室     [当前项目 ▾]                 同步状态 / 添加项目
项目总览 | 代码探索 | 改动分析 | 迭代方案 | 编码准则
─────────────────────────────────────────────────────
当前页面标题、说明及主要操作
内容区：按页面显示报告、画布、文件列表或方案
上下文区：所选文件、符号、证据与下一步操作
```

项目总览展示规模、质量依据、优先问题、依赖和提交节奏。代码探索整合画布、聚类、执行流程、路由、循环依赖和路径追踪，避免在总览里塞十个同级按钮。改动分析展示当前 Git 改动及其影响面。迭代方案展示已有方案、验收项和实际核对结果。编码准则独立显示规则、启用状态与内置技能。

窄屏使用可换行或滚动的主导航，内容改为单列；图谱提供列表替代和显式缩放、复位操作；详情放在内容下方。页面应有初始加载、无项目、无结果、请求失败、操作中、完成反馈与重试状态。移除图谱需明确只移除索引及其后果，执行前确认。

## 功能完善

### 项目与代码探索

- 添加、切换、同步和移除项目形成完整流程；同步后更新提交号、建图时间和统计。
- 页面记住所选项目和页面入口；失效选择自动回到可用项目。
- 项目或节点切换时取消读取或丢弃过期结果，避免显示上一项目的数据；卸载后不更新组件。
- 搜索、图谱节点、文件详情和影响分析互相跳转，给出当前范围与截断数量。
- 保留静态分析限制和 inferred 关系说明，不把未识别的动态依赖描述为不存在。

### 改动与迭代

- 复用现有 workingChanges、changedSymbols 和 impact，在页面提供 Git 当前改动分析；非 Git 目录显示明确说明。
- 复用 readPlans，显示真实保存的方案、功能点及核对状态，提供方案详情和用户触发的重新核对。
- 核对复用现有 checkPlan，与 eng_plan 使用同一实现。读取与写入操作在接口和 UI 中明确区分。

- 快捷任务继续通过当前 DSH 会话执行；复制指令需报告剪贴板失败，不能伪装为已经执行任务。

建议同时覆盖“本插件自身规范”和“工作室提供给模型的规则”。保留四条通用工程准则，并增加独立规则页面，允许编辑及启停一份全局附加规则；先不做跨项目规则继承系统。

附加规则保存到工作室数据目录，展示实际生效内容，保存成功后才更新内存设置和系统提示词；明确这些规则会用于所有会话，不把全局规则误称为仅当前项目规则。项目已有 AGENTS.md/CLAUDE.md 仍由 eng_workspace 发现并提示模型读取，不写回项目约定。已有 principles 开关保持原有含义，新字段缺失时按无附加规则读取。无效文件和保存失败应可见。

默认不把本插件的 Tailwind/Vue 写法强加给其他项目；规则示例可由用户主动采用。规则文本是提示词约束，不能声称可自动证明生成代码合规。

## 代码组织与准则

- Host 入口只组装生命周期和注册项；页面请求、工程查询、方案操作与设置持久化分别由明确模块负责。
- 请求与响应采用按 action 区分的类型映射，页面不能随意选择 call<T> 返回类型；解析在 HTTP 输入和持久化文件处执行。
- 相同操作在模型工具与页面中复用领域实现；不复制方案核对、体检或影响分析算法。
- 页面按功能拆分组件，通用请求状态与项目选择独立，画布布局纯计算从 Vue 组件抽出。
- .vue 方法名使用 camelCase；模板不写 as 等 TypeScript 断言；事件转换在 script 中完成。
- 新增注释和非显然导出说明使用中文，保持局部、准确；不使用无说明的 any、空 catch 和静默成功。
- 使用 Tailwind 工具类和集中维护的基础组件样式，避免各页重复手写视觉规则。
- 增加 Vue 类型检查和可执行规范检查，检查模板断言及方法命名；选择 Vue 官方工具，并以锁文件记录依赖。
- 不为达成文件长度数字而机械拆文件；模块按职责和测试边界划分。
